# Contributing

Agent skills and plugins in the [Agent Plugins](https://agent-plugins.org) format.

- `skills/<skill>/` holds every skill as real files.
- `plugins/<name>/skills/<skill>` is a symlink to `../../../skills/<skill>`.

## Rules

- A plugin is closed: every skill one of its skills links to as `../<skill>/SKILL.md` is also in the plugin. `bun run validate` fails otherwise.
- A plugin ships `plugin.json` and `skills/`, nothing client-specific.
- Register each plugin in `.devin-plugin/plugin.json` and `.claude-plugin/marketplace.json`.
- No `AGENTS.md` or `CLAUDE.md` at the repo root. The root installs as a plugin, and a root `AGENTS.md` would be injected into every session as an always-on rule. Shared agent instructions live in `docs/AGENTS.md`.
- Never commit secrets. Skills read them from the environment.
- Run `bun run check && bun run check-types && bun run validate` before opening a PR.

## Skill provenance

Imported skills carry `metadata.github-*` fields generated by `gh skill install` where supported. `skill-sources.json` catalogs verified upstreams across the personal collection, including skills not vendored here. System and bundled skills are excluded.

`upstream-comparison-commit` identifies the revision inspected for provenance; it is not a claim about the original installation revision. `local-body-modified: "true"` means the preserved body differs from that revision. Before updating a skill, compare local changes and preserve intentional customizations; do not blindly overwrite with `gh skill update` or `--force`. Supporting files may also have local changes and need review.

Humanizer uses a root-level `SKILL.md` unsupported by the installed GitHub CLI's discovery. Its source metadata was verified through GitHub's API; use its recorded source path directly instead of assuming the CLI can reinstall it. Do not invent source attribution for local or unverified skills.
